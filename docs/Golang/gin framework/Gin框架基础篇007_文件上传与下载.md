在现代Web应用开发中，文件上传与下载是常见的功能需求，如用户头像上传、文档下载、媒体资源处理等。Gin框架提供了简洁而强大的文件处理能力，本文将详细介绍如何在Gin中实现文件上传、下载以及相关优化策略。

## 1. 文件上传

### 1.1. 单文件上传

单文件上传是最基础的文件上传功能，适用于只需要上传一个文件的场景，如头像上传、简历上传等。

* 在Gin中，单文件上传主要通过 `c.FormFile()` 方法获取上传的文件。

* 如果需要保存文件，可以使用 `c.SaveUploadedFile()` 保存到指定位置.



**示例：**

```go
func TestUpload(c *gin.Context) {
	// 获取上传的文件
	file, err := c.FormFile("file")
	if err != nil {
		c.JSON(200, gin.H{
			"message": "上传失败",
		})
		return
	}
	// 保存文件
	err = c.SaveUploadedFile(file, "upload/"+file.Filename)
	if err != nil {
		c.JSON(200, gin.H{
			"message": "保存失败",
		})
		return
	}
	c.JSON(200, gin.H{
		"message": "上传成功",
	})
}
```

### 1.2. 多文件上传

在需要同时上传多个文件的场景，如批量图片上传、多个文档上传等。可以使用 `c.MultipartForm()` 方法获取多个文件，然后遍历处理。



**示例：**

```go

func TestUploadMulti(c *gin.Context) {
	// 获取上传的文件
	form, err := c.MultipartForm()
	if err != nil {
		c.JSON(200, gin.H{
			"message": "解析失败",
		})
		return
	}
	files := form.File["files"]

	// 保存文件
	for _, file := range files {
		err = c.SaveUploadedFile(file, "upload/"+file.Filename)
		if err != nil {
			c.JSON(200, gin.H{
				"message": "保存失败",
			})
			return
		}
	}

	c.JSON(200, gin.H{
		"message": "上传成功",
	})
}
```

### 1.3. 内存大小限制

`gin.Engine`中提供了一个`MaxMultipartMemory`属性，用于设置解析多部分表单时最大的内存限制。

> 当调用http.Request的ParseMultipartForm方法时会使用这个值来控制内存使用量。

**特别注意：** `MaxMultipartMemory`参数定义了将请求体存储到磁盘之前，内存中可以缓存的最大字节数。如果上传的文件大小低于该参数，文件会被加载到内存中处理；如果上传的文件大小高于该参数，文件会被直接写入临时磁盘文件，不会因为超过内存限制而失败。





示例：

```go
router := gin.Default()

// 设置内存限制
router.MaxMultipartMemory = 8 << 20
```

## 2. 文件下载

文件下载功能允许用户从服务器获取文件，Gin提供了多种方式实现文件下载：

* `c.File`： 直接将指定文件的内容发送到HTTP响应体中。
* `c.FileAttachment`：将指定文件的内容发送到HTTP响应体中，并且会以指定的文件名称设置Content-Disposition请求头信息，因此浏览器通常会直接按照给定的文件名称下载文件。
* `FileFromFS`：将指定文件系统中指定文件的内容发送到HTTP响应体中。
* `Data`：将字节数组写入应答体的通用方法，可以用于写入文件内容。
* `DataFromReader`：流式写入数据到应答体中，可以用于写入文件内容。

### 2.1. 直接文件响应 File 

 `c.File()`方法会将文件内容直接发送到HTTP响应。

该方法会将指定路径的文件内容作为HTTP响应体发送给客户端。如果没有设置Content-Type，方法会根据文件扩展名自动设置Content-Type。方法不会自动设置Content-Disposition，这意味着浏览器可能会在新窗口中显示文件内容（如图片、PDF等），而不是下载。如果想要浏览器直接下载文件，需要手动设置Content-Disposition。

**示例：**

```go
package main

import (
    "fmt"
    "os"
    
    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.Default()
    
    // 提供文件下载
    r.GET("/download/:filename", func(c *gin.Context) {
        filename := c.Param("filename")
        filepath := fmt.Sprintf("./uploads/%s", filename)
        
        // 检查文件是否存在
        if _, err := os.Stat(filepath); os.IsNotExist(err) {
            c.JSON(404, gin.H{
                "error": "文件不存在",
            })
            return
        }
        
        c.File(filepath)
    })
    
    r.Run(":8080")
}
```

### 2.2. 强制下载 FileAttachment

与`c.File`方法类似，但 `c.FileAttachment()`方法会自动设置Content-Disposition为attachment，强制浏览器下载文件而不是在浏览器中打开。
此方法特别适用于需要确保文件被下载而不是在浏览器中直接显示的场景。

**示例：**

```go
r.GET("/download-attachment/:filename", func(c *gin.Context) {
    filename := c.Param("filename")
    filepath := fmt.Sprintf("./uploads/%s", filename)
    
    // 检查文件是否存在
    if _, err := os.Stat(filepath); os.IsNotExist(err) {
        c.JSON(404, gin.H{
            "error": "文件不存在",
        })
        return
    }
    
    // 使用FileAttachment自动设置下载头
    c.FileAttachment(filepath, filename)
})
```



### 2.3. 从文件系统下载 FileFromFS

使用 c.FileFromFS()从指定的文件系统中提供文件下载，这在需要限制访问路径或使用虚拟文件系统时非常有用。
该方法允许你使用 Go 的 `embed.FS` 或 `http.FileSystem` 接口来提供文件服务，可以更好地控制访问权限和安全性。

**示例：**

```go
r.GET("/download-fs/*filepath", func(c *gin.Context) {
    // 使用http.Dir创建一个文件系统
    fs := http.Dir("./uploads")
    
    // 获取请求的文件路径
    requestedFile := c.Param("filepath")[1:] // 去掉开头的"/"
    
    // 从文件系统提供文件 - 参数顺序应为 (filepath, fs)
    c.FileFromFS(requestedFile, http.FS(fs))
})
```

### 2.4. 从字节数组下载 Data

使用 `c.Data()`方法从字节数组提供文件内容，适用于需要在内存中生成内容后下载的场景。
该方法接收状态码、内容类型和字节数组作为参数，直接将字节数组内容作为响应体发送。适用于小文件或已经加载到内存中的数据。

**示例：**

```go
r.GET("/download-data/:filename", func(c *gin.Context) {
    filename := c.Param("filename")
    filepath := fmt.Sprintf("./uploads/%s", filename)
    
    // 读取文件内容到字节数组
    fileBytes, err := os.ReadFile(filepath)  // 使用 os.ReadFile 替代已废弃的 ioutil.ReadFile
    if err != nil {
        c.JSON(404, gin.H{
            "error": "文件不存在",
        })
        return
    }
    
    // 设置响应头，强制下载
    c.Header("Content-Description", "File Transfer")
    c.Header("Content-Transfer-Encoding", "binary")
    c.Header("Content-Disposition", "attachment; filename="+filename)
    c.Header("Content-Type", "application/octet-stream")
    
    // 使用Data方法发送字节数组
    c.Data(200, "application/octet-stream", fileBytes)
})
```

### 2.5. 流式下载 DataFromReader

与c.File和c.FileAttachment不同，c.DataFromReader()是真正的流式下载方法，可以从任何实现了io.Reader接口的对象读取数据并流式传输。
该方法适用于需要完全控制数据流的场景，如处理大文件、网络流或其他数据源，有效避免内存溢出问题。

> 虽然c.File方法内部使用了Go标准库的http.ServeFile，通常会使用操作系统提供的零拷贝技术（如sendfile）来传输文件，不会将整个文件加载到内存中，但c.DataFromReader()提供了更灵活的流式传输方式，特别适合处理非文件类型的数据源。

**示例：**

```go
r.GET("/stream-download/:filename", func(c *gin.Context) {
    filename := c.Param("filename")
    filepath := fmt.Sprintf("./uploads/%s", filename)
    
    file, err := os.Open(filepath)
    if err != nil {
        c.JSON(404, gin.H{
            "error": "文件不存在",
        })
        return
    }
    defer file.Close()
    
    // 获取文件信息
    fileInfo, err := file.Stat()
    if err != nil {
        c.JSON(500, gin.H{
            "error": "获取文件信息失败",
        })
        return
    }
    
    // 设置响应头
    c.Header("Content-Disposition", "attachment; filename="+filename)
    c.Header("Content-Type", "application/octet-stream")
    
    // 流式传输文件内容
    c.DataFromReader(200, fileInfo.Size(), "application/octet-stream", file, nil)
})
```
