# 知识沉淀机制（knowledge-mkdocs）

本工作区包含个人知识库 `knowledge-mkdocs`（MkDocs 项目，根目录含 `mkdocs.yml`）。
只要该项目在工作区中，就按本规则持续运作；它不在工作区时本规则不生效。
本机制与学科无关——学技术、学外语或任何主题都适用。

## 职责
在本工作区的任何工作 / 学习过程中，持续留意**出现过、但知识库尚未（完整）收录的知识点**，
并在阶段性节点让用户决定是否沉淀。沉淀撰写的具体方法见 `knowledge-capture` skill。

## 知识库是通用的
知识库面向任何读者，不是某个项目或某次会话的工作记录。
知识点可以来自具体项目，但写进知识库时必须**去掉来源痕迹**：不出现项目名、公司名、人名、
本机路径、真实账号密钥，也不出现"第 N 步""这次""实测""跟做时"这类过程叙述。
一个没参与过这次工作的人，读完不应感到疑惑。详细规则见 skill 的"通用化规则"。

## 收集（全程后台进行，不打断主任务）
- 维护一份本会话"候选知识点"清单，记录过程中涉及到的每一个知识点。
- **不做预筛选**：粗到原理 / 机制 / 方法，细到语法 / 命令 / 术语，都要记下。筛选权在用户。
- 每条附一句简述，以及遇到它时的上下文（在做什么时出现的）。
  上下文只用于会话内的核对和规划，**不写进知识库**。

## 节点汇报（到达阶段性节点时）
触发节点：一个子任务 / 一个学习小节完成、切换主题、用户说"到这""下一个"、或用户主动要求"沉淀一下"。

到达节点时：
1. 按 `knowledge-capture` skill 的方法，对照知识库核对每条候选项的覆盖度，
   分类为 `[无]` / `[不全]`，丢弃 `[已覆盖]`。
2. 按 skill 的方法为每条候选项**规划落点**：放进哪个目录、哪个文件（新建还是补写既有文件的哪一节）。
3. **以"目标文件"为单位**向用户汇报（格式见 skill"汇报格式"）：每个文件写明
   目标目录、文件名、新建 / 补写、要编写的内容要点。
   所有候选项（含语法等细粒度条目）都要归入某个文件的内容要点里，不能遗漏；
   不要按主题列出逐条的大表格。
4. 请用户勾选要落盘的**文件**（可回复文件编号 / 全选 / 跳过），
   也可以对某个文件删减内容要点、改目录或改文件名。

## 落盘（仅限用户勾选后）
- 只写用户勾选的文件和内容要点，未勾选的一律不写。
- 加载并遵循 `knowledge-capture` skill 完成撰写与 `mkdocs.yml` 导航更新。
- 勾选了多个文件时，**每个文件单独开一个工作流并行撰写**（做法见 skill"并行撰写"），
  不要在主会话里一篇一篇地写。
- 落盘前后不做用户未要求的其它改动。

## 静音
用户说"本次先别沉淀 / 暂停沉淀"即在本会话内停止收集与汇报，直到用户说恢复。
